# 控制器接入、上游更新与空间管理

新版载荷为 format 4，只包含控制器适配层。0.0.6 的 format 3 通过独立启动器接入，存在 macOS 菜单栏图标注册问题；更早的 format 2 替换整个 MXU。

## 保留上游 MXU

新补丁保留原版 `CFBundleExecutable`，由 `Contents/MacOS/` 下的上游 MXU 直接启动。工具只在现有 Mach-O 头部空闲空间添加一条指向包内适配层的 `LC_LOAD_DYLIB`，保持各 section 内容、偏移、构建 UUID 和 entitlements，并刷新程序及应用签名。头部空间不足或结构不支持时，在替换应用前报错。适配层按自身位置读取 `runtime.json`，不依赖全局环境变量或启动器，也不修改 PlayCover 设置。

这样避开 LaunchServices 启动器经 `execv()` 切换 GUI 程序引发的菜单栏图标故障。适配层还转发原应用委托的 Reopen 回调，并在没有可见窗口时恢复普通主窗口，使 Dock 图标可以唤回已隐藏的窗口。

界面将 EndPlayDesktop 声明为原生支持的 `PlayCover` 控制器，并通过 `uuid=maa.endplaydesktop` 标记。适配层在动态加载 MaaFramework C API 时，只将带此标记的创建请求转为 `MaaCustomControllerCreate`。普通 PlayCover 控制器继续使用原实现。键盘、鼠标、滚轮、相对移动、截图和输入释放复用现有私有 sidecar 通道，不依赖某一版 MXU 的内部实现。

原版 Agent 可执行文件不修改。接口中的启动命令经运行环境转交给原 Agent，保持参数和 IPC 标识；仅对 EndPlayDesktop 将 `PI_CONTROLLER.type` 转为上游支持的桌面类型 `MacOS`，避免错误进入移动端 UI 分支。适配层未加载时会中止 Agent 启动。使用时请打开正常的 `MaaEnd.app`，不要直接运行包内原版程序。

MaaEnd 更新后，重新应用补丁以恢复控制器声明、启动入口和任务兼容标记。重新应用保留更新后的 MXU、Agent、框架和业务资源。上游控制器 API、动态加载方式、签名策略或框架 ABI 的不兼容变更仍可能需要更新适配层；这不等同于保证未来所有版本都无需适配。官方应用自身的启动目录或更新故障也不由旧版 MXU 绕过。

## 从旧补丁迁移

本次验证以完整官方 MaaEnd 首次安装补丁为准，不保证所有旧补丁状态均能直接迁移。建议先重新安装官方 MaaEnd，再应用新版补丁，任务配置无需删除。工具保留已有的同版本原包备份恢复处理；缺少需要的原包时会停止操作。

如果已经清空 Runtime，重新应用新版工具即可安装当前运行环境。已有配置可能仍保存旧控制器的地址字段，迁移后请重新选择 EndPlayDesktop、输入实际 MaaTools 地址并点击连接。任务配置无需删除。

## Runtime 与备份

`~/Library/Application Support/EndPlayDesktop/` 中的 `runtimes/` 按版本与构建标识复用。应用补丁、恢复或清空备份成功后，工具自动清理不再引用的 Runtime，以及可重新解压的 `payloads/` 缓存。

工具记录处理过的 MaaEnd 路径，也从备份中发现其他安装。当前安装、保留备份及正在执行的补丁运行环境会受到保护。未知文件夹和符号链接不会作为缓存删除；读取安装记录失败时停止自动清理并写日志。手动复制到其他位置、且从未被工具记录的应用无法自动发现，清理前应先在工具中对该副本应用一次补丁。

“清理闲置运行环境”可以手动触发相同回收。“清空备份…”列出数量并再次确认，删除本工具保存的所有安装路径的备份，然后回收它们独占的 Runtime。删除备份不修改当前 MaaEnd 或任务配置，但不能再恢复到这些历史状态。旧 v1 安装若仍依赖备份恢复 Agent，需先完成迁移。工具不自动删除用户保留的恢复点，因此长期保留大量备份仍会占用空间。

## 验证范围

原生测试覆盖原版入口直接加载适配层、动态加载拦截、普通控制器透传、私有协议中的键鼠与截图操作、含空格路径、子进程退出清理及 Reopen 回调转发与隐藏窗口恢复。首次接入时还使用 MaaFramework v5.14.3 与 v6.0.0-alpha.1 的真实公共 API 配合模拟设备验证了连接、PNG 截图、右键、键盘、滚轮、相对移动及输入释放；未由这些测试操作真实游戏。
